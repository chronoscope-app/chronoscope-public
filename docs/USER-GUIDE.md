# Chronoscope 0.16.4 user guide

The same guide is available offline from **Help → Full user guide** in the app.

## Welcome workspace

An empty, unsaved session starts with **Open data**, **Try a demo** and **Recent workspaces**. Open reviews CSV, Excel or GIS data, or restores a saved .chronoscope file. Demos are bundled for offline exploration. Successful Open and Save actions remember up to eight portable workspace paths on this device; **Clear list** removes those shortcuts without changing files. Missing files report an error so you can locate them using Open. Choose **Continue with an empty workspace** or a view in the toolbar to enter the map without data. Tab moves between controls, Enter activates them, and F1 opens Help. In dialogs, Tab stays inside and Escape closes the dialog and returns focus.

## Guided local analysis

Choose **Analyze** in the toolbar, or **Results → New analysis**. No SI model or API key is required. Start with **Profile data**, **Find duplicates**, **Find outliers** or **Summarize trajectories**. Choose All Events, Filtered Events or Selected Events within filters, and optionally one Event layer. Fields use canonical and original source column names.

Profiles accept up to 16 fields; duplicate groups accept up to eight. Outliers require one numeric field and an IQR or population z-score threshold. Trajectory statistics join recorded samples per entity with WGS84 geodesics, exclude missing locations and disclose same-time conflicts; they do not reconstruct continuous routes. Duplicate matches use only the chosen fields and never delete source records. A duplicate result row selects one explicitly labelled example Event, not its entire group.

Analyses run through the Rust job system with progress and Cancel. Completed results open in Results with counts, exclusions, parameters, scope and source revision, and persist in portable workspace saves. The original Events are unchanged. Data changes mark earlier results stale and prevent selecting their old source rows. SI can still create other supported analysis plans.

## Events and entities

An **event** is one timestamped record. It may also have a location, WKT geometry, category and other attributes. An **entity** groups events belonging to the same person, vehicle, storm or other subject. For example, 20 timestamped records for one hurricane are 20 events belonging to one entity. Tracks connect successive events of that entity.

The visibility checkbox shows or hides an entity. The **plus-circle** adds all of its events to the selection without clearing other selections, including events outside the current filters. A selected entity shows a **minus-circle**; click it to remove all of that entity’s events while keeping other selections. This also clears a partially selected entity. Use the left and right pane collapse/expand buttons to make more room for the map.

Events were called observations in earlier versions. Existing workspaces, recovery data and source column names remain readable; original imported labels and attributes are preserved.

## Table selection and desktop controls

Click a table row to replace the selection. **Shift+Down/Up** extends or shrinks an inclusive range from its fixed anchor, including across the continuous table. Arrow keys select a single row; Home/End jump to the first/last record, Page Up/Down move by the visible table height, and Ctrl/Cmd+Shift+Down/Up selects to the end/start. Keyboard ranges follow the current sort and table scope. Ctrl-click on Windows/Linux or Cmd-click on macOS toggles an individual row. Shift-click selects an inclusive block from the last clicked anchor; Ctrl/Cmd+Shift-click adds the block to the selection. Ranges follow the current source, filters, sort column and direction, including across the continuous table. Changing sort or table scope resets the anchor. Selection remains synchronized with the map and other views.

App labels, rows and controls do not drag-select as website text. Text fields, documentation and copyable command/output surfaces retain normal text selection.

Open the **playback controls** popup using the sliders icon at the bottom of the time rail. Its **rabbit menu** sets playback speed from **0.25× to 2×** in quarter-speed steps (1× by default). The step menu chooses **Millisecond, Second, Minute, Hour, Day or Week**. At 1×, playback advances one selected UTC increment per real second; the rabbit multiplies that rate. Day is the default and the increment is remembered on this computer. Changes take effect immediately without moving the current play position; the chosen speed also applies after pausing and resuming. Play advances a continuous time cursor and a focus marker on the time axis with a single data refresh in flight; playback does not rescale the geographic frame. In the time rail’s **Playback controls**, **Fade** defaults to on. Entering markers fade in over 0.18 seconds; departing markers, tracks, trails and stems fade out over 0.8 seconds. Afterimages are visual only. Turn Fade off to retain playback history until the next loop: the ordinary time filter grows, keeping the table, selection and exact queries consistent with the map. Rendering budgets still apply. Turning Fade back on during playback restores the moving window. The choice persists in workspaces and saved views. Reduced-motion settings disable visual transitions. Existing map imagery stays visible during camera and event updates while replacement tiles load. In Time view, geography extends across the visible ground; the UTC axis retains its inset reference position. Four on-map grab spheres follow the viewport edges and stay clear of the navigation toolbar. Near the natural horizon or geographic world boundary they move inward to remain on real ground. Hidden layers are removed immediately; unchanged visible layers can reuse their previous imagery until fresh tiles arrive.

## Display, clustering, density and heat maps

**Views** in the right inspector controls entity visibility, entity colors and display layers. Saved camera/filter views and selection groups are available through **Saved views…**. **Tracks · between records** toggles lines connecting records of the same entity. **Stems · to map** toggles the vertical drops from space-time objects to the map. The toggles are independent and persist in workspaces and saved views. **Automatic clusters / points** is the default: above 2,000 matching located events, exact-count grid summaries replace most individual markers. Zoom and the time window refine them. Below the threshold, individual points return. Choose Points to retain bounded representative markers, or choose Count clusters explicitly.

Click a cluster to select all exact members, open their attribute table, or zoom to their extent. A one-record cell selects that event. Box selection selects whole cells by their displayed centers. Selected counts color their cells; selection also appears in the table. Cluster positions summarize events; they are not measured coordinates. Space-time count clusters divide starts into fixed UTC time slabs, automatically about 24 per time window; choose a minute width to override. The status bar reports the resulting cell count; exact coarsening metadata is available through display_data. Entity/source partitions apply to count clusters; density and heat maps combine partitions. No source records are deleted.

**Density** colors exact event counts in each hierarchical Web Mercator grid cell. It is counts per cell and time slab, not events per square kilometre. **Heat map**, off by default, smooths the exact pre-binned count or nonnegative value weights with an approximate compact kernel in a background worker. Missing/negative value weights contribute zero. Radius controls influence in display pixels; optional reference zoom scales it with the map. The default maximum is relative to the view; set a fixed maximum to compare views. Heat-map colors represent approximate kernel overlap, not probability or a calibrated scientific KDE. Grid summaries and globe geographic resampling are visual approximations. Source data remains queryable.

In **Views**, enable Events, Tracks, Stems, Clustering, Density cells, Heat map or Bloom. Tracks and Stems toggle independently; their sliders change line opacity. The event slider changes marker size. Clustering and density are alternative summaries; heat map and bloom can combine. Heat controls kernel smoothing radius; Bloom coordinates ground spread, exposure strength and threshold. More does not change the source data or time window. Advanced parameters retain exact numeric overrides.

**Bloom**, also off by default, draws overlapping soft coral footprints on the ground with shared glow and additive count contributions. It uses fine exact-count grid summaries, without large cluster discs or count labels. Strength, ground spread/radius and brightness threshold control the effect; values are Chronoscope settings, not ArcGIS parameters. It adds rendering cost and shows view-relative brightness, not a scientific density estimate. Heat map and bloom both combine the current filtered time window on the map/terrain surface, including space-time. Bloom keeps Events visible when enabled, including unselected markers, within the configured marker budget. Events and their enabled tracks keep their time heights above it; changing time height never raises either effect. Map imagery and elevated events do not emit bloom. Heat is draped over the loaded native terrain mesh; void cells retain no terrain triangles. Display settings persist in saved workspaces and views and are accessible to CLI/MCP via view_set and scene_sync. display_data returns exact-count summaries and cell descriptors; query/attribute_table/select_query accept display_cell, and select_query also accepts a homogeneous display_cells union.

Spatial culling is enabled by default. Rust filters time and geography before binning and keeps a bounded display packet. Stems simplify to a default two-pixel tolerance, retaining endpoints, selected events and inferred time-only triangles. Three-hour gaps, entity boundaries, reversed time and dateline crossings break stems; use zero gap minutes to disable the gap threshold, or zero pixel tolerance for full displayed vertices. Dense summaries do not create stems between aggregate positions. The original stored geometry never changes. The Points display still has a representative budget; a simplified line is not a source trajectory export.

## WKT geometry import and display

Map a **WKT geometry** column in CSV/Excel import, or accept detection from headers such as geometry, geom, wkt, geometry_wkt and matching sample values. Each record still needs the usual timestamp. A nonempty WKT column takes precedence over other coordinate columns; unmap it to use DD/UTM/MGRS instead.

Supported Simple Features: POINT, LINESTRING, POLYGON with interior holes, MULTIPOINT, MULTILINESTRING, MULTIPOLYGON and GEOMETRYCOLLECTION, including EMPTY and Z/M/ZM forms. Original text is retained in the canonical geometry_wkt field and CSV export. X means WGS84 longitude and Y latitude; no automatic axis swap. Optional EWKT SRID=4326 works; other SRIDs must be reprojected before import. Z/M values are retained but do not control altitude or time. CRS-definition WKT and curved/solid extensions are not implemented.

GeoRust validates grammar and topology. Open rings, self intersections, nonfinite/out-of-range coordinates and unsupported projections are rejected with row review. Split antimeridian-crossing segments at ±180° into multipart geometries before import. No implicit projection or coordinate padding is used. Polygon Events have explicitly labelled derived surface centroids; full boundaries remain intact.

Map and space-time show lines and polygon boundaries, with hole-aware fills on flat surfaces. Terrain/globe use boundaries instead of coarse polygon fills that could cut through relief. Shapes can be clicked, selected from the table, filtered, edited in the inspector, exported and saved. Geographic filters test actual shape intersection, including holes, using indexed envelope candidates. Polygon and multipolygon Events retain full geometry and also have explicitly derived surface-centroid scalar coordinates for marker/track and point-based analysis. Other non-point shapes without a polygon centroid retain null scalar coordinates and are excluded by point-only tools. Non-point geometry does not become a time-only triangle.

Geometry rendering is bounded to 1,000 features and 200,000 source vertices in the UI; refine filters when the status reports a geometry budget. WKT records have a 512 KiB text, 50,000-vertex and 32-level nesting limit. The renderer uses WGS84 geographic projection for flat modes and WGS84 ellipsoid coordinates for Globe; source coordinates are unchanged. Geometry projects use ZIP or SQLite containers; centroid/GIS projects use version-5 metadata and require Chronoscope 0.14 or newer.

## GIS files and polygon centroid Events

Use **Open** for Shapefile (.shp), vector GeoPackage (.gpkg), GeoJSON, TopoJSON, KML/KMZ, CZML, GPX, local 3D Tiles (tileset.json) and glTF/GLB. JSON is identified by content. **Add reference layer** preserves native geometry, styles and supported animation, including timeless features. **Import as Events** opens timestamp/entity mapping and validation; layer settings can also convert a packaged source later. Models require an explicit WGS84 longitude/latitude/ellipsoidal-height anchor and scale.

**Tables** lists every Event layer and GIS layer with an attribute table, including hidden layers. Each layer opens as a tab in one attribute-table panel. Scroll horizontally through all supported columns, which load automatically as needed. The search box searches this tab’s record text and original attributes, including columns outside the visible area, without changing workspace filters. Each tab retains its search, sort and scroll position for the session. Its × closes that tab. Detach moves the whole group into a separate movable, resizable window; Dock or the window close button returns it to the workspace. Event tables can respect workspace filters or show every record in the layer. Double-click a tabular GIS layer for the same searchable, sortable, continuously scrolling attribute table. Ctrl/Cmd-click and Shift-click select multiple rows. Reference selection is separate from Events, with a 1,000-record limit; native animated tracks can represent several source samples. The ellipsis/right-click settings provide naming, visibility, Fit, Events conversion and removal. CZML/GPX follow the shared focus/Play time. Reference layers do not automatically inherit Event filtering, clustering or analysis.

Polygon and multipolygon Events retain their complete shapes and receive a **derived surface centroid** circle/track anchor by default. Disable **Views → Polygon centroid markers and tracks** to hide anchors while retaining shapes. WGS84 geodesic edges are densified to at most 25 km and integrated on the authalic sphere; holes subtract, multipart areas add. The inspector and `location_kind` identify the derivation. Centroids can lie outside concave polygons or in holes. Point-based analyses use centroids, while geographic bounds still intersect full geometry.

Portable Save embeds local companion assets in the existing SQLite .chronoscope container with version-5 metadata. Recipients need no original source folders. CZML remains an import/presentation format; it does not replace the indexed workspace, filters, table state, map stack and DTED. GIS/centroid projects require Chronoscope 0.14 or newer. Native reference layers allow 50,000 extracted features; Events conversion allows 250,000 per GIS input. Text files are bounded to 64 MiB, individual assets to 256 MiB, packages to 512 MiB/8,192 files and a workspace to 64 layers/2 GiB. Larger analytic inputs should use Events/CSV clustering or tiled content.

Only linked local companions are collected; external URLs, KML NetworkLinks/refresh and rich XML descriptions are disabled during display. Original attributes/descriptions remain in the Rust table. General CRS and GIS vertical-datum conversion are not performed: GeoJSON/TopoJSON must be WGS84, native source altitude-mode/transform semantics apply, and model anchors use WGS84 ellipsoidal metres. GIS Z values remain in consistent-dimensional WKT but do not become Event altitude. Native loader feature/extension limitations still apply. Shapefiles require matching .shx, .dbf and WGS84 WKT1 .prj files; .cpg can declare the DBF text encoding. Only standard dBASE III attributes and XY Point, Polyline, Polygon and MultiPoint geometry are supported; pack deleted DBF records before import. Vector GeoPackage combines up to 64 EPSG:4326 XY feature tables into one reference layer, retaining table names in source_layer (or chronoscope_source_layer when the input already uses that name). Source feature IDs include the table name. Both readers normalize to GeoJSON and retain original source files in portable workspaces. Binary inputs, including Shapefile companions together, are limited to 64 MiB; normalized output also has a 64 MiB limit. Z/M, MultiPatch, curved geometry, GeoPackage imagery/elevation, and general CRS conversion are not supported. NULL geometries retain attributes; non-NULL empty GeoPackage geometries need export to NULL first. GeoPackages must be closed/checkpointed, with no pending WAL changes. Geodatabases, I3S services and new raster/terrain formats remain unsupported.

CLI/MCP operations: `file_probe`, `gis_load`, `gis_layers`, `gis_set`, `gis_remove`, `gis_read`, `gis_table` and `gis_import_preview`. The last returns the ordinary import ticket for reviewed `import_commit`. Reference attributes and asset reads are bounded; file scope and mutation controls use the existing engine.

## SI chat (Super Intelligence)

Open **SI** in the top bar, then its **settings gear → SI service**. Enter an OpenAI-compatible Chat Completions base URL (such as https://api.openai.com/v1), an exact model name with tool support, and an API key if required by the service. Local compatible services can use HTTP on localhost, with an optional key. HTTPS SI services can request a user certificate through native OS authentication on macOS/Windows. The OS/card provider handles certificate and PIN access. SI settings → Client certificate offers an optional server-specific identity or anonymous override. Linux requires compatible PKCS#11 middleware and an explicit certificate identity, as for protected WMTS maps. Reconnect to forget SI session certificate choices. Keys/PINs are never exported into projects. Browser SSO portals are not supported. Connect closes setup and opens a conversation in the lower-right panel. Send messages there; Enter sends and Shift+Enter adds a line break. The gear button opens connection settings; × closes the chat without ending an active request. Custom Anthropic/Gemini protocols require a compatible gateway; a generic URL alone does not translate their APIs.

The assistant calls the same validated Rust operations exposed through CLI/MCP. Filtering, selection, analysis and views work by default. Tick **Allow record changes** for editing/deletion/aggregation. Expand Permissions in chat to optionally allow a folder for scoped import, open, save, export and terrain loading. A folder is not required to connect. Remove access revokes the connection-scoped grant without resending a key. Save a copy before requesting changes. There is no shell execution. Tool outcomes appear below the answer; verify the evidence in the workspace.

Requested data and tool results go to the chosen service, which may charge for requests. Keys remain in memory until disconnect or app exit, never in project files or logs. Endpoint/model settings stay local; reconnect after restart. Follow-ups remember up to 32 messages / 96 KiB in memory, dropping oldest complete turns. Long history messages are explicitly truncated. Only prompts and final answers are remembered; tools re-query current state. New chat, reconnect, disconnect and app exit clear history; it never enters saved projects or logs. Failed/cancelled turns are not remembered, although completed actions remain. Requests run at most 8 steps by default (16 through CLI), 32 tool calls and five minutes, with no automatic network retries. Stop cancels before the next tool; an in-flight HTTP call can take up to 60 seconds to return. Completed actions remain and data edits can be undone. New requests see current workspace state.

## Time and proximity aggregation

Use **Aggregate during import** in the import dialog to reduce retained records before building their indexes. CSV is processed in bounded batches with disk-backed grouping; the entire file must still be read and parsed. Excel uses its existing bounded workbook loader. The original file is unchanged.

For loaded data, choose **Aggregate** above the scene, set window minutes and radius metres, then preview exact counts. Creating summaries replaces the entire workspace with summaries of the visible records and excludes hidden records. It clears old selection/groups/saved views; session Undo restores the preceding workspace. Save a separate original first. Summaries save and reopen normally.

Time windows are UTC epoch-aligned half-open buckets: a 15-minute window groups 10:00–10:14, then 10:15–10:29. Each event must lie within the WGS84 ellipsoidal radius of its first anchor and share entity, category and source. This is order-dependent anchored grouping, not transitive clustering; input/import order can affect groups. The anchor coordinate, source row and original attributes are representative, not merged facts. Time/end cover the group, value is the mean of nonempty numeric values, and `chronoscope.aggregate.*` attributes record counts and options. Missing locations remain separate. Individual rows are not retained in summaries; keep the source. Already aggregated records cannot be aggregated again without the original data.

## Getting started

Chronoscope explores events in space and time. Choose **Open** for a .chronoscope workspace or a CSV/Excel data file. Workspace files restore the saved setup; data files open the import preview. For data, review the detected columns, then select **Validate and import**. Each event needs a timestamp. Locations are optional: unlocated events remain available in the table, timeline, filters and applicable analyses. Triangles show time-only events when visible located events of the same entity/source bracket their timestamp. Their display position follows time along the shortest WGS84 geodesic; it is an estimate, never an observed coordinate. Unbracketed or ambiguous antipodal routes remain in the table/timeline. Circles show observed locations. Entities connect events into tracks.

The **64-pixel time rail** sits between the entity pane and the map. It shows the event distribution vertically, with earlier times at the top. Drag either handle to resize the UTC window; its Start or End date appears beside the handle until release. Drag the selected spine to move both bounds. Up/Down adjusts time; Shift takes larger steps and Alt takes the smallest step. The clock icon opens exact UTC range entry and Full range; the sliders icon opens playback settings. Both popups remain available when the rail is independently collapsed to 24 pixels. Hover or click an icon to open its popup, and press Escape or click outside to close it. Collapse is remembered on this computer.

The centre canvas is the main workspace. The sidebar starts with **Entities** and **Categories**. Each heading has a column menu for grouping the list by a canonical or imported field. Checkboxes filter those values and the Entities selection buttons add/remove their matching records; choosing another column does not rewrite source entities or track identities. Colors can be edited while the Entities list uses the Entity column. Blank/missing field values are grouped together. Each alternate list is limited to 5,000 values and a bounded text payload; a limited list is explicitly marked. Use Attribute rules for values beyond that list. Column choices and visibility travel with workspace filters. Use the sidebar to filter, the timeline to limit time, and the inspector to examine selections, run patterns, view charts or save contexts. Use the collapse arrow in either pane heading to leave a vertical icon rail. Hover an icon to use its floating panel; moving off dismisses it and keeps your changes and drafts. Click or focus an icon for keyboard access, use Up/Down to choose a section and the arrow toward the canvas to enter its controls. Escape closes the panel. Pin keeps the whole pane open; pane sizes and collapsed states are remembered on this computer. Collapse either side pane to enlarge the map; its rail retains an Expand button. Light, dark and system appearance are available in Preferences.

## Import and detection

Supported sources: CSV, TSV, XLSX, XLS and XLSB. CSV delimiter detection recognises comma, semicolon, tab and pipe; quoted cells are respected. Excel worksheets are individually selectable. Headers and sampled values suggest timestamp, coordinates and related fields. Always review the preview, especially unfamiliar columns. Every suggested mapping can be changed.

Map **Timestamp/date** to a combined date-time column or a date column. For separate date and time, also map **Separate time**. FIRMS acquisition-date and acquisition-time headers are recognised, including compact HHMM clocks and numeric HMM values that lost a leading zero. Map Entity, Category, Label, Numeric value, Related entity and End timestamp where relevant. Default entity fills absent entity values. Original columns and source row numbers are retained as attributes and provenance. Append combines data; leaving it off replaces the data workspace. Replacing can be undone.

Import uses one scrollable window with a field grid. Choose the worksheet, delimiter and append/replace option, then adjust mappings in place. Green shading marks auto-selected or manually mapped fields that validate in the first six source rows. Light red shading marks missing required mappings and values that cannot be validated; each card explains what needs attention. Optional unmapped fields stay neutral. Date order is available beside the timestamp mapping; other coordinate/date settings and aggregation remain under their additional sections. Feedback and the converted UTC sample update automatically as mappings change. **Refresh sample validation** retries that sample check. **Check all rows** validates the complete source into a disposable disk store without changing the workspace and shows its results in the same window. It reports valid Events, rejected rows, missing locations and duplicate candidates. Candidates match canonical identity, time, location and descriptive values; original attributes can differ. Missing locations and duplicate candidates are retained. Rejected rows require an explicit acceptance checkbox. Changing mappings or import options clears the previous full-file check and disables import until the updated settings are checked again. **Export rejected-row report** writes every rejected source row number, original source cells and reason as formula-protected CSV, even when the displayed examples are limited. Existing report files are not overwritten. Source changes invalidate the ticket; preview the source again. Large reviews need temporary disk space and can be cancelled. Import recipes are retained in the saved workspace. CSV/TSV imports stream into the indexed workspace, with safety limits of 2 GiB per input, 50 million rows and 512 columns; those limits are not a performance guarantee. Excel and legacy in-memory import use a 64 MiB file limit and four million cells. Large workspaces need free disk space for the indexed working database, journals, autosave and a separate portable save.

## Dates, clocks and fractional seconds

Stored timestamps retain **seconds and fractions** in UTC: `08:15:01`, `08:15:59` and `08:15:59.123456` are distinct instants. Canonical storage, CLI/MCP and rendering use binary64 Unix seconds (about 0.24 microsecond spacing near 2026). This is magnitude-dependent precision, not exact nanosecond storage; finer input may round to the nearest representable instant. Original source strings remain in imported attributes. Time filters, edits, ordering, encounters and speed calculations use these fractional timestamps. Playback increments include millisecond, second and minute rates as well as hour/day/week. Chart intervals include milliseconds, seconds and minutes; Individual timestamps keeps unbucketed instants. ISO start/end events such as `2025-01-01T11:28/2025-01-01T14:42` preserve both endpoints. A month-only `2025-01` covers the full month through the last representable instant before the next month. An explicitly mapped end column overrides the inferred end. Date-only events use midnight; this is a representation convention, not a measured hour. Pattern analyses use event start times; coarse dates and intervals require care when interpreting findings. Offsets in timestamps take priority over the assumed UTC offset setting, which applies to dates/clocks without an explicit timezone.

Automatic parsing recognises ISO/RFC3339 and RFC2822, numeric year-month-day, day/month and month/day forms, English abbreviated or full month names, compact YYYYMMDD, YYYYMMDDHHMM and YYYYMMDDHHMMSS, ISO week and ordinal dates, Chinese date separators, 24-hour HH:MM clocks, seconds/fractions, AM/PM and compact clocks. Unix seconds, milliseconds, microseconds and nanoseconds are recognised by magnitude; explicit encoding overrides detection. Excel native date cells are decoded; serial dates use an explicit Excel 1900 or 1904 encoding when needed. Excel fractional-day clocks can be combined with a date column. Excel's fictitious 1900-02-29 is rejected.

Values such as `03/04/2026` are ambiguous. Unambiguous sampled dates may determine day/month order; otherwise select **Day first** or **Month first**. Two-digit years 00–68 represent 2000–2068; 69–99 represent 1969–1999. Time-only columns require a date column or a default date. The time-of-day encoding also recognises Excel fractional-day clocks. Unknown timezone abbreviations and invalid calendars are rejected instead of guessed.

Use a custom chrono format for specialised inputs: `%d/%m/%Y %H:%M:%S` or `%Y-%m-%d %H:%M`. A custom format takes priority and must match the source, including seconds if present. For fractions use `%Y-%m-%d %H:%M:%S%.f`. For separate columns, supply a combined format or a date-only format. Decimal commas in numeric fields can be enabled. All display times and exact filter ranges are UTC.

## Coordinates and MGRS accuracy

All coordinates use WGS84. Decimal degrees accept latitude/longitude columns, hemisphere suffixes and a combined `latitude, longitude` field. Select the correct field order manually if needed; combined fields use latitude first. UTM requires easting, northing, zone 1–60 and hemisphere N/S, either in columns, explicit defaults, or a combined `18N 585664 4511315` field. A UTM latitude-band letter is not an N/S hemisphere. No default zone is silently assumed.

MGRS accepts spaced or compact, lower- or uppercase references and precision from a 100 km square to a 1 m grid: `18T WL 8566 1131` and `18TWL85661131` are the same 10 m square. Digits are split equally into easting and northing. Eight total digits give 10 m precision; six give 100 m, four give 1 km and two give 10 km. Odd digit counts are invalid. Missing digits are handled within each half, never appended to the entire coordinate string.

A short MGRS reference represents an area. Chronoscope places its marker at the square's centre, preserves the entered precision in the inspector, and reports grid size. Converting that centre to a 10-digit reference would imply false accuracy, so its display keeps the source precision. Editing decimal-degree coordinates resets that source precision. Polar MGRS/UPS conversion is supported; map services may have limited polar coverage. Choose DD, UTM or MGRS display in Preferences.

## Navigate and select

In navigation mode, left-drag moves the view. Wheel, right-drag and double-click zoom toward the pointer; right double-click zooms out. Holding the wheel button and dragging rotates/tilts in Globe and Time; Ctrl-drag or Shift-drag provides an alternative in navigation mode. Shift-wheel tilts; Ctrl/Cmd-wheel rotates; Alt/Option-wheel uses finer zoom steps. Map stays flat and ignores tilt gestures. Sync views can rotate its heading; N restores north. Movement stops when the gesture ends; there is no inertia, free-look or automatic tilt while zooming. Camera tilt gestures are limited to 85 degrees, and camera navigation stays above the geographic floor. Camera altitude never changes event times, the selected time window or Time height.

Click the map to give it keyboard focus. Arrow keys pan; Shift+arrows rotate/tilt in 3D views; N restores north, U looks straight down, F/R fits events, and Page Up/Down zooms. Shift+Page Up/Down changes camera altitude in 3D views; Alt makes steps smaller. O switches Map/Globe. These navigation shortcuts do not capture keys from tables, sliders, fields or other panes. Space retains timeline play/pause. Escape stops an active drag before clearing selection. Double-click zoom preserves the previous selection; single-click picking waits briefly to distinguish it. ## Patterns and charts

**Find patterns** runs a statistical screen over all currently filtered records, or selected records within those filters. It pauses playback before capturing the scope and runs locally with progress and Cancel. Empty field choices use Value and up to seven numeric imported columns, excluding coordinate/calendar/identifier-named columns; automatic discovery examines at most 512 numeric column names. Scan options lets you choose up to eight numeric measurements, minimum record count (20 by default), relationship strength (|r| ≥ 0.6), and outlier fences (1.5 × IQR). Field names do not establish units or meaning. Methods and coverage shows exact numeric, excluded and missing/blank counts; calculations do not sample records. Identical numeric columns are disclosed and screened once. The scan checks IQR outliers, pairwise-complete Pearson field/time associations, unusually long consecutive source/entity gaps, and fixed-UTC event-count FFT timing candidates. Gap cutoffs exceed both the IQR upper fence and three times the pooled positive-interval median. Timing candidates require at least three cycles and 20% of positive-frequency power across 12–128 buckets. Empty count buckets mean zero observed records, not proof of no real-world activity. Correlations and spectral scores are descriptive screens, without significance tests or causal claims; repeated events need not be independent. Different collection schedules, gaps, mixed groups and valid extremes can explain a candidate.

Each candidate has methods, up to five example records, and **Select supporting records**, which selects its complete evidence set and opens the actual attribute table. Shift-click adds. Gap evidence includes both interval endpoints; other relationships include all complete numeric pairs. Selection is exact up to one million records; larger requests fail explicitly rather than selecting only examples. Four bounded scan reports are cached in memory for this app session, keyed by data identity/version, filters, scan options and relevant selection. Presentation-only changes and unrelated selection changes reuse results. Changes to the scope mark the previous results stale and disable evidence selection until Find patterns is pressed again; stale/expired evidence is also rejected by the engine. No scanning runs automatically while moving the time window. Closing and reopening the app clears this temporary scan cache. **Spatial and custom analysis** retains the targeted controls below.

Patterns run on visible events, with an optional selected-only scope. Proximity finds different entities observed nearby within a time tolerance; Stationary requires repeated events within a radius over a duration and rejects large sample gaps; Speed flags successive samples exceeding the chosen threshold. Gaps identifies long event intervals; Clusters groups nearby events in space and time. Clusters can link points through intermediate events, so a cluster is not necessarily one simultaneous meeting. Configure radius (metres), tolerance/duration/gap (seconds), speed (km/h), and cluster size in the Patterns inspector.

Results are candidates based on samples, not proof of an event or a route between samples. Sparse data, source timestamp precision, MGRS grid uncertainty and gaps affect interpretation. Computation and result limits bound expensive analyses; a partial-result indication is shown if reached. Click a finding to select its evidence. Changed data or filters can make old findings stale; rerun the analysis. Charts builds ECharts bar, line, area, scatter, histogram, Tukey boxplot, weekday/hour grid and period comparison views from canonical or imported fields. Start with eight shortcuts: **Compare groups**, **Change over time**, **Distribution**, **Relationship**, **Compare spread**, **Repeating patterns**, **Composition over time** or **Compare periods**. Spread compares boxplots; patterns shows a linked UTC weekday/hour grid; composition stacks group counts over time. Compare periods shows paired bars, changes and percentages; Comparison periods accepts full UTC dates/times including fractions. Starts are included and ends excluded; overlaps are rejected, unequal durations disclosed, and zero/missing baselines have undefined percentages. Counts are recorded Events, not inferred activity or independent entities. Empty count cells mean zero recorded Events; empty measurement cells mean missing data. Scoped Events outside both periods are counted separately. Clicking a pattern cell or period bar selects its exact source Events on the map and table. All eight retain scope and layer; none enables spatial heat maps or bloom. Starters use real numeric schema counts and exclude coordinate/calendar/identifier-named fields from measurement suggestions; names alone do not establish meaning. Use **Customize** to choose any supported fields and calculations. **Charts** is the second inspector tab, after Views. **Field roles…** lets you classify canonical/imported columns as Measurement, Category, Identifier, Date/time, Coordinate, Currency/unit, or Exclude from suggestions. Explicit measurements override name guesses but still need actual numeric values; categories guide Compare groups. Automatic resets one assignment. Search, Assigned only and Show 100 more handle wide tables. Apply saves roles with the workspace; Cancel discards the draft. Roles support undo/redo and are dataset metadata, unaffected by saved views. They guide new starters without changing existing chart fields, source values, Event Time mapping or precision, or converting units/currencies. Date/time and unit roles classify reference columns; use import mapping to change the Event clock and chart labels for known units. Choose **All Events**, **Filtered Events** or **Selected Events**; Selected respects current filters. The layer selector appears when multiple Event layers are present. Group into series and choose count, sum, mean, minimum or maximum. Time axes offer UTC millisecond/second/minute/hour/day/week/month/year buckets. Chart options include stacked series, a second Y field for bar/line/area charts, an ordinary least squares trendline for scatter, histogram bins and the displayed mark budget. Trendlines use all complete pairs, including records beyond the displayed mark limit. Boxes show quartiles and median, observed whiskers within 1.5 interquartile ranges and bounded outlier marks. Missing/non-numeric values are excluded where numeric measurements are required, and counts and display limits are shown. Calculations run in Rust against a revision-bound, disk-backed read snapshot; source records are retained. Click a mark or use a scatter rectangle brush to select its exact source records on the map and in the attribute table; Shift-click adds. Open attribute table shows the normal sortable source table with the shared selection. Charts open in a wider pane beside the map. Drag the existing pane divider, or focus it and use arrow keys, to resize; **Compact chart** shows a small linked chart card over the map; **Widen chart** restores the full controls. Chart notes remain available in the card. The saved chart name appears above the plot. Customize → Title, labels and units edits presentation labels without changing values or converting units. Automatic Value units/descriptions use explicit source value_unit/value_description fields only when uniform and nonblank across the entire chart scope. No unit is inferred from examples. Missing measurements offer an Event-count fallback; bounded time charts offer explicitly coarser UTC intervals. Source ranges and Inspect spread and outliers help examine extremes without removing them. **Select displayed Events** selects only the Events represented by displayed marks. Save named chart presets under Saved charts; they travel in workspace files and saved views. Counts and statistics describe observations, not necessarily independent entities; a trendline is descriptive association, not causation.

Streets is the single built-in basemap: OpenFreeMap Positron, enabled automatically with detailed streets and buildings where mapped. No account, API key or provider selection is required. The same native Cesium imagery tiles work in 2D, space-time and globe views, and drape over DTED terrain. MapLibre rasterizes vector tiles using one bounded offscreen context; Cesium owns the displayed camera, imagery LOD and terrain. Maps opens the Streets switch. Advanced map settings provides Add custom map server, custom layers, cache and credits. There is no built-in WMTS catalog. Existing saved server connections and custom layers are retained. A previous unmodified local NASA default upgrades to Streets; older saved projects retain their explicit map configuration. Use Streets only disables custom overlays without deleting their configuration. The OpenMapTiles/OpenStreetMap credits remain visible and appear in captures. Data and map availability vary by region and provider; public hosting has no uptime guarantee. Streets assets use the same Rust disk cache and offline setting as custom maps. For custom WMTS, enter a service URL and read capabilities to choose layer, matrix, style, date and resolution. Multiple custom layers, opacity, order and zoom rules remain available in Advanced settings. On macOS and Windows, HTTPS automatically handles server requests for client certificates through native OS TLS. On macOS, available identities are filtered by client-auth validity and the requested issuer chain; a unique match is selected automatically, otherwise a native chooser appears. The OS/card middleware owns PIN prompts. Linux currently requires compatible PKCS#11 middleware and an explicit certificate URI. Maps → Advanced → Authentication provides optional exact-origin identity overrides, anonymous mode and session reset; no per-server setup is needed for native automatic mode. PINs/private keys are never accepted or saved. Overrides stay local and are not included in projects. General reprojection and browser SSO/OAuth are not implemented.

New profiles start with Balanced world terrain: bundled offline USGS GMTED2010 elevations at one arc-minute spacing (approximately 1.9 km), with EGM96 heights. Terrain stays compressed on disk; nearby blocks are decoded in memory. Ocean-only blocks are omitted and ocean height is zero. Missing land elevations remain void. Terrain → Unload terrain persists across restarts; Restore bundled terrain enables it again. Existing terrain preferences are retained. The built-in world layer is referenced by portable workspaces instead of copied into each save. To replace it, load a DTED Level 0, 1 or 2 file, or a folder containing DTED tiles. Terrain uses WGS84 horizontal coordinates and mean-sea-level heights. The renderer drapes WMTS rasters over the terrain mesh. Fit terrain shows its coverage; exaggeration affects display only. Missing/void heights remain uncovered. Unload removes terrain from the workspace. Unsupported datums, malformed tiles and checksum failures are reported.

Raster requests load the full plan at the selected matrix resolution in small pages, composited progressively into one viewport texture bounded to 4096 pixels per edge. Multiple layers share an approximately 32-megapixel CPU canvas budget, so many overlapping sources reduce effective resolution. Panning/zooming requests the visible region; automatic level follows the camera. Stop loading cancels active downloads while retaining cached tiles. Normal access defaults to eight workers and no imposed request delay; native client-auth transport may serialize requests. Known built-in layers display linked attribution in the scene, and canvas PNG/MCP captures append a credits footer. Maps → Advanced → Cache and loading configures concurrency, optional pacing, disk limit (8 GiB by default; 0 unlimited), tile freshness (30 days by default), clear cache and cache-only offline access. Capabilities cache for one day. This is a direct private disk cache, with no proxy/server needed. Offline mode reuses even older cached resources and fails clearly on a cache miss. HTTP 429 imposes a cooldown with no automatic retries. Our public-server testing uses restrained settings separately. NASA/server availability and network access can affect first load; data exploration still works with the map disabled. A saved project contains map settings, not downloaded imagery. Contacting the configured provider reveals its requested viewport; events are processed locally.

## Save, share and reopen

**.chronoscope** is the native portable workspace format. It uses versioned ZIP or indexed SQLite containers. New saves use version-7 metadata and SQLite v3 (or a ZIP manifest), including fractional-time support. GIS companion assets are embedded and checksummed. Save stores all imported/edited events and attributes, filters, selections, groups, saved views, current camera/view (including 2D zoom and globe), map-layer stack/order/opacity/zoom rules, layer visibility, attribute-table source/sort/options, time height, geographic extent, table/inspector layout, theme, coordinate display, terrain exaggeration, map configuration and import recipes. Loaded terrain is embedded, so recipients need no original CSV, Excel or DTED files.

Use Save for the current file and Save a copy for another filename. Send the bundle to another Chronoscope user and open it normally. Older ZIP and SQLite v1–2 workspaces still open and migrate while preserving their saved instants. Compatible legacy `.chrono.json` files still open. Previously discarded seconds cannot be recovered automatically: reimport the original CSV/Excel for full precision. New version-7 workspaces require an altitude-capable build (Next 0.16.0 or later). Saving JSON preserves data and setup but references terrain on disk; use .chronoscope for portability. CSV exports are data extracts and do not carry workspace configuration.

Saves use a temporary file and atomic replacement. Bundle manifests are limited to 64 MiB and terrain to 512 MiB total/32 MiB per tile. Loading validates versions, paths, expanded sizes, resource consistency and terrain before extraction. Resources extract into the app's user data directory; they contain no executable plugins. Cached project-assets directories may be removed when no open/referenced workspace needs them. Large workspaces use indexed SQLite v3 (v1–2 files remain readable) under the same .chronoscope extension; DTED stays embedded. Working copies, backup and journals require several times the workspace size in free disk space. Representative rendering defaults to 20,000 markers. Preferences → Display → Marker budget can explicitly request up to 100,000; the choice stays in this workspace and larger datasets still use representatives. The status bar reports matching events, rendered count, budget and LOD. Queries, aggregates and Select visible use every matching event. Box/click selection targets displayed representatives; zoom or refine filters for detail. Camera-driven point and shape requests refine the visible region while preserving workspace filters. Pattern analysis has an explicit input budget and reports limited results. Automatically save unsaved work is enabled by default in Preferences. Chronoscope writes an atomic local .chronoscope copy every 30 seconds while the app is available and before opening a workspace, starting a data import or native Quit/Close, without prompting. On macOS these files are in `~/Documents/Chronoscope/Autosaved`; the exact folder is shown in Preferences. Other platforms use their Documents/Chronoscope/Autosaved folder. A custom --data-dir profile uses Documents/Autosaved inside that profile instead. Autosaved- files hold current-session copies; Recovered- files hold abandoned previous-session checkpoints, archived automatically at startup without changing the current workspace. Open these files normally to continue work. Automatic copies preserve rows, selection, filters, bookmarks and display settings; external terrain references stay local. They never overwrite the explicitly saved source document. Use Save/Save a copy for a portable deliverable with embedded resources. Disabling this preference restores Save/Continue without saving/Cancel. Previous-session recovery alerts appear quietly in the top-right Notifications bell; launch never opens a recovery chooser. Click the bell to recover a checkpoint, open an automatically saved recovery copy, or review a recovery error. Dismiss hides an alert for this session without deleting saved work; Delete checkpoint remains a separate confirmed action. The working database still checkpoints after a two-second quiet period, targeting at most thirty seconds while changing. A process or disk failure can lose changes since its last durable checkpoint. Unsaved undo history and pattern results are not restored.

## Troubleshooting and about

If import fails, check delimiter, worksheet, mappings, ambiguous date order, timezone assumption and UTM zone/hemisphere. A time-only value needs a date. Seconds are accepted but invalid clocks still fail. Input must already use WGS84; reproject other datums before importing. If a marker seems displaced, verify source datum, DD field order, UTM hemisphere/zone and MGRS cell precision. Geographic flat views and Globe retain polar event coordinates; the WMTS raster compositor stops at approximately 85.0511° latitude. Distance analysis uses the WGS84 ellipsoid. Terrain exaggeration is labelled in the scene. Choose EGM96 MSL or WGS84 ellipsoid explicitly in Terrain; unresolved MSL is not displayed. EGM96 uses the bundled 15-minute NGA geoid grid to convert display heights; original source elevations are unchanged. Space-time height represents time and is never exported as physical altitude. If nothing is visible, reset filters, disable selected-only and fit.

If terrain is missing in an older JSON project, load it again from Terrain and save as .chronoscope. For map errors, confirm layer/matrix/time settings, network and provider availability; disable the map to continue offline. If graphics initialisation fails, check WebGL2 support and current OS/WebView drivers. Use the CLI for data validation without graphics. The application writes bounded diagnostic logs under its user-data logs directory; logs record command, revision, outcome and duration, without event values, arguments or tokens. Agent tools expose diagnostics and enforced schemas. Long operations can run through job_start, job_status, job_result, job_cancel and job_release. Prefer expected_revision, dry_run and idempotency_key for edits. Undo covers data edits and saved objects; navigation does not consume edit undo.
