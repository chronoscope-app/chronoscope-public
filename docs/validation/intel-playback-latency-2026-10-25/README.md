The repair starts from Next main `88dc05b`. Product commit `3e6f789` changes the browser loopback command transport and avoids an unnecessary filter write when pausing full-range playback. It preserves fresh-state reads, revision conflicts, filter rebasing, native Tauri dispatch, rendering quality, display budgets and every existing playback acceptance limit. No server socket policy or cached-state optimization was introduced.

The original Intel release runs recorded 16–17 updates in 3.5 seconds. Profiling separated engine execution from browser response delivery: the filter command used about 1 ms in the engine and 5 ms on the browser network timeline, while the parsed response reached JavaScript about 39 ms after the response body had finished arriving. Three serialized command/body completions made each playback update expensive. Replacing browser `fetch` plus a separate body read with one asynchronous `XMLHttpRequest` completion and JSON parse reduced that scheduling overhead. Native commands continue through Tauri.
