# Dataset credit in portable projects and exports

The version-6 project schema accepts an optional `provenance` array of dataset-level records: `title`, `creator`, `source_url`, `license`, `license_url`, `changes`. Older files without it load unchanged. Records persist in JSON, portable ZIP and SQLite projects, including autosave metadata; no 3,439-fold duplication in Event attrs is needed. Older application versions may discard this new optional field: retain a companion credit when sharing with them.

The bundled Black Rock Forest sample credits **Scott LaPoint (2026), Hudson Highlands Wildlife Connectivity Project**, [DOI 10.5441/001/1.652](https://doi.org/10.5441/001/1.652), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Selection: LYRU_0003, LYRU_0004 and PEPE_0001, 1–7 March 2023, visible/unflagged/located observations, no thinning/interpolation. Columns were mapped to Events; original timestamps and attributes remain. This does not imply endorsement.

Normal desktop/CLI/MCP workspace CSV export writes `<output>.attribution.json` and returns that path. **Share the CSV and sidecar together.** CSV has no metadata header convention and remains schema-compatible. Every successful normal workspace export writes a companion, even for uncredited data (`[]`), so an overwrite cannot leave stale credit from a different dataset. Both payloads are serialized/validated and synced before either destination is replaced. Ordinary replacement errors restore the previous outputs (or remove newly created outputs); rollback failures are reported with recovery-copy locations. Two renames are **not crash-atomic**: abrupt process/OS failure or concurrent filesystem changes can still leave a partial pair. Do not distribute failed/partial outputs. Low-level event-only export functions and legacy frontends cannot infer project metadata: callers must use `project::export_csv_attributed (coordinated pair export)` or supply the credit separately. Chart images, screenshots and extracted subsets likewise need the dataset credit alongside them; map-provider credit alone is not dataset credit.

CSV-sidecar **reimport is not automatic**. Importing/replacing a workspace from CSV reads its rows, not the companion; keep the sidecar and supply its credit separately. Replacement import intentionally does not inherit an unrelated previous workspace’s credit. Appending rows retains the current workspace credit but does not acquire incoming sidecar metadata. For a provenance-preserving round trip use a `.chronoscope` project. Aggregate carries existing credit and appends the aggregation parameters/change annotation, including through undo/redo.
