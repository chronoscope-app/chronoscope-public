# Dense-data display and storage

Imported rows cost disk, indexes, working memory and query time. They do not automatically create Cesium objects. Frame rate depends on visible glyphs, geometry, labels, trails, raster pixels and effects; a heavy concurrent query can still delay a view update.

## Defaults and meaning

**Display → Automatic clusters / points** is the default. Above 2,000 matching located events it displays exact-count grid summaries. Zoom and time filters refine them; individual events return below the threshold. **Heat map and Bloom are off by default.** Spatial culling and two-pixel trail simplification are on. Settings persist in scene state, saved views and portable workspaces. Points mode retains the existing 20,000 representative budget (100,000 opt-in), rather than promising to draw every imported row.

| Mode | Meaning |
| --- | --- |
| Auto | Reversible count clusters above the threshold, points below |
| Points | Bounded representative events plus selected evidence within budget |
| Count clusters | Exact counts, optionally partitioned by entity or source |
| Density | Counts per projected cell and UTC time slab, not per unit ground area |
| Heat map | Approximate compact kernel overlap from exact pre-binned count/value weights |
| Bloom | Overlapping additive ground footprints with layer-wide glow; view-relative brightness only |

Rust filters time/geography before grouping into a hierarchical Web Mercator grid, up to level 24. Camera zoom and pixel spacing choose a requested level. The UI receives at most 4,000 cells (8,000 via display_data) and 32 UTC start-time slabs. The engine coarsens space and then time as necessary, reports actual resolution, and never truncates counts. Excessive entity/source partitions fail explicitly. In map/globe the current filtered time window is combined spatially; space-time clusters/density default to roughly 24 slabs. Heat and bloom combine the filtered window on the ground in every geographic view; their cells have no time slabs. In space-time, bounded source events remain elevated at their time heights. Duration events use the ordinary interval filter and are assigned to slabs by start time. There is no additional camera-height time filter.

Slabs use Euclidean division, including before 1970. +180° wraps to −180° for bin identity. Cell descriptors preserve their viewport restriction, including wrapped bounds. Polar event coordinates remain available in native geographic flat modes and Globe; the intermediate WMTS raster coverage separately stops at approximately ±85.0511°. Single-record cells use source coordinates. Multi-record positions are means within their cell, with circular longitude at level zero: **summary display positions, not measurements or geodesic centroids**. Missing locations and non-point WKT are excluded from grids, with their existing table/timeline/geometry paths retained.

Click a summary for exact members, member attributes or zoom. The member-table cell scope is temporary; select members and save a group/view to retain that membership. Bounded selected events and valid time-only triangles remain available in dense views; triangles keep null source coordinates and unbracketed events stay in the table/timeline. Box selection targets whole cells by displayed center. query/attribute_table/select_query accept display_cell; select_query also accepts a homogeneous display_cells union. Use expected_revision when acting on a displayed scene. Decimal u64 identity and stored coordinates/precision remain unchanged. The separate **Aggregate** operation replaces rows with lossy summaries; it is not the reversible display mode.

## Heat and effects

In 0.13.3, **Display → Heat map** and **Display → Bloom** enable immediately with automatic settings. Heat uses event counts, a bounded 24–64 CSS-pixel radius chosen from visible record density and canvas area, view-relative color maximum and no fixed reference zoom. Bloom uses theme-aware, bounded defaults. Detailed overrides are under **Advanced display settings** and validate before sending a command. Both effects remain off by default; these are visual heuristics, not scientific bandwidth optimization.

A worker bilinearly splats bin weights into bounded 512×512 rasters and applies an O(pixels) separable triangular kernel. This is a pre-binned **visual approximation**, not Esri code, scientific geodesic KDE, probability or density per square metre. Nonnegative value weights omit missing/negative values. The camera resolution converts CSS-pixel radius to separate X/Y raster bandwidths; optional reference zoom scales influence. Globe uses geographic raster resampling, with more distortion near poles. Requests include a kernel margin for immediate offscreen contributions. Finite rasters clip kernels at world edges; inspect dateline hotspots regionally. The legend declares overlap units and automatic versus fixed color maxima. Density/heat maps combine partitions.

Heat and bloom stay on the map/terrain in space-time, 2D and globe views. Bounded worker-generated atlases become native Cesium imagery layers, so the same native terrain provider drapes imagery and effects. Local DTED voids remain absent from its terrain triangles. Time filters determine contributions; the time-height control never raises the effects. This is display draping, not an altitude measurement.

Bloom uses soft coral ground emission without count discs or labels. A fine target grid (up to 4,000 exact-count cells) retains more detail than ordinary clusters; coarsening is disclosed by cell count/resolution. The worker splats count contributions, normalizes exposure against the emission distribution, applies a bright-pass threshold and a separable compact blur, and tone-maps the resulting glow into the ground atlas. Kernel normalization keeps radius changes from multiplying energy uncontrollably. Overlap can brighten toward white. This is an approximation at summary centers, not a draw of every source event. The worker never reads imagery or elevated-object pixels, and Cesium's whole-scene bloom postprocess is not enabled. Strength, normalized radius and threshold are Chronoscope controls, not interchangeable ArcGIS values. Worker/atlas replacements use generation guards and dispose stale resources; pixel tests independently verify actual visibility and exclusion from unrelated surfaces.

The entity legend collapses with its header and resizes from its lower-right corner. Content scrolls when it exceeds the panel; refreshes preserve its size and collapsed state. Display counts appear in the status bar. The time histogram has start/end brackets and one movable interval. Drag either bracket to resize, or drag inside the interval to translate both bounds without changing duration. Arrow keys adjust either endpoint or move the interval; Shift uses larger steps, Alt uses minute steps, and Home/End move to the dataset boundaries. Full range removes both bounds. The time-focus guide is a labeled outline, not an additional filled surface.

Style references: [Esri bloom guidance](https://developers.arcgis.com/javascript/latest/visualization/high-density-data/bloom/) describes additive brightness and glow for overlapping point features. [Esri HeatmapRenderer](https://developers.arcgis.com/javascript/latest/references/core/renderers/HeatmapRenderer/) documents approximate kernel overlap. Chronoscope independently implements its grid and ground-effect worker and uses Cesium imagery for draping. It does not copy Esri rendering code or claim identical output. ArcGIS FeatureEffect has its own [2D/heatmap/clustering restrictions](https://developers.arcgis.com/javascript/latest/references/core/layers/support/FeatureEffect/); Chronoscope’s ground draping in 3D is our extension.

## Performance boundaries

Grid summaries use the shared bounded 8 MiB cache keyed by data/filter/viewport/grid. Exact selected counts overlay separately through indexed selected IDs, so a selection change can reuse base bins. Camera requests are debounced and single-flight, coalescing to the latest viewport. Stale generations/revisions cannot publish. The camera envelope is conservative, especially in tilted space-time views.

Clusters use a batched native point collection and at most 80 count labels. Space-time density uses native geometry instances at UTC slab heights; ground density uses an imagery atlas. New heat generations terminate previous workers. Imagery, geometry and workers are disposed on replacement. Iterative Douglas–Peucker simplifies displayed trails with a work bound and safe full-detail fallback. It protects endpoints, selected evidence and inferred triangles, and breaks at entity/time reversals, dateline crossings and configured gaps (default three hours). Zero tolerance retains displayed vertices. Representative source sampling still limits Points-mode trails; these are not trajectory exports.

Cold SQL queries still scale with matching rows. Persistent multiresolution pyramids, out-of-core vector tiles and analytical GPU KDE are not implemented. WKT retains its separate geometry budget. Bounded drawing/transfer is not a universal million-row FPS guarantee. Software Linux rendering validates behavior, not physical GPU throughput or Mac/Windows drivers. This prototype uses WebGL2, without a WebGPU renderer. See [validation](VALIDATION.md).


The Views bloom slider uses t = amount/100: strength = 0.2 + 2.2t, radius = 0.02 + 0.72t³, threshold = 0.18 − 0.16t. This coordinates perceptual brightness and ground spread while the footprint exposure still compensates for area. Heat smoothing uses radius = 4 × 32ᵗ CSS pixels. Exact numeric overrides remain available; old workspaces keep their values until the user adjusts a slider. Neither mapping is a scientific density calibration.

Display sliders preview on input while the pointer is held. Native marker/line resources update or rebuild as needed; effect parameter changes generate a replacement worker atlas. Backend commits are single-flight and coalesce intermediate values. Save waits for the final display commit. Attribute tables retain at most 100 data rows in the DOM and fetch successive windows during continuous scrolling; the dataset is not capped to that window.
